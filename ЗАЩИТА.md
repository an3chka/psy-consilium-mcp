# Защита PsyConsilium MCP

## План выступления на 7 минут

1. **Проблема, 40 секунд.** Для выбора лечения врачу нужны шкалы, соматические ограничения, исследования и инструкция препарата. Эти данные находятся в разных источниках.
2. **Решение, 40 секунд.** PsyConsilium принимает обезличенный случай, считает показатели, сравнивает три подхода и проверяет введённую врачом дозу.
3. **Архитектура, 60 секунд.** Шкалы работают через собственный stdio MCP. Соматические расчёты предоставляет локальный MCP на порту 8000. PubMed и OpenFDA подключены как внешние MCP из Glama. Все вызовы идут через единый router.
4. **Безопасность, 45 секунд.** Красные флаги останавливают обычный сценарий до внешнего поиска. Расчёты выполняет детерминированный код. Система использует только синтетические или обезличенные данные.
5. **Результат демо, 60 секунд.** Показать три варианта, баллы применимости и отдельные источники для каждого варианта. Подчеркнуть, что баллы не равны вероятности выздоровления.
6. **Доза, 45 секунд.** Врач вводит плановую дозу. OpenFDA возвращает начальную дозу, титрацию, максимум и предупреждения. Система проверяет план, но не выписывает рецепт.
7. **Соответствие заданию, 50 секунд.** Кратко показать stdio, порт 8000, внешние MCP, timeout, cache, UI из JSON Schema и JSON-RPC inspector.
8. **Вывод, 30 секунд.** Польза проекта состоит в проверяемом происхождении каждого вывода и разделении ответственности между инструментами.

## Двухминутное демо

1. На странице «Обзор» запустить готовый демо-кейс.
2. Показать PHQ-9, GAD-7, BMI, функцию почек и QTc.
3. Прокрутить к сравнительной матрице лечения.
4. Открыть один источник PubMed и показать применимость исследования.
5. Показать блок дозировки: план 50 мг и найденный максимум 200 мг/сут.
6. Открыть JSON-RPC и показать `tools/list` либо `tools/call`.

## Вероятные вопросы преподавателя

### Почему MCP, если можно использовать REST API?

MCP задаёт единый контракт discovery и вызова инструментов. Приложению не нужно знать отдельный интерфейс каждой системы. Через один router работают локальный процесс, HTTP-сервер и внешние источники. В инспекторе виден единый JSON-RPC протокол.

### Где собственные MCP-серверы?

Первый сервер работает через stdio и предоставляет PHQ-9, GAD-7, AUDIT-C и каталог. Второй работает на порту 8000 и предоставляет BMI, CKD-EPI, Cockcroft-Gault, QTcF и Child-Pugh.

### Какие внешние MCP использованы?

PubMed MCP выполняет поиск и получает данные публикаций. OpenFDA MCP возвращает официальную американскую маркировку препарата. Оба выбраны из каталога Glama.

### Почему нельзя доверять найденной статье автоматически?

Поисковая выдача сама по себе не доказывает применимость. Поэтому проект отдельно проверяет совпадение проблемы, вмешательства, взрослой популяции и дизайна исследования. Полный текст всё равно должен оценить врач.

### Система назначает лечение?

Нет. Она ранжирует варианты для обсуждения и проверяет план, введённый врачом. Балл не является вероятностью успеха. Финальное решение принимает врач.

### Почему система показывает дозировку?

Она не генерирует дозу. Врач вводит плановую дозу, после чего система сопоставляет её с разделом `dosage_and_administration` официальной инструкции и показывает ограничения.

### Насколько безопасны данные пациента?

Модель случая не содержит ФИО, контактов и номера карты. Наружу уходят только грубая возрастная группа, клиническая проблема и препарат-кандидат. Для защиты используется синтетический кейс.

### Что произойдёт, если внешний MCP недоступен?

Вызов ограничен таймаутом 12 секунд и повторными попытками. Успешные ответы кешируются на 15 минут. Ошибка сохраняется в JSON-RPC журнале, а система явно снижает уверенность вывода.

### Это настоящий коллоквиум врачей?

Сейчас это независимые структурированные роли в одном алгоритме: клинический координатор, специалист по доказательной медицине, психофармаколог, соматический специалист и методолог. Это не пять автономных языковых моделей. Такое решение делает учебный прототип воспроизводимым.

### Что требуется для реального использования?

Нужны актуальные локальные клинические рекомендации, проверка взаимодействий по валидированной базе, клиническая валидация, аудит безопасности, защита персональных данных и регистрационные процедуры медицинского изделия.
